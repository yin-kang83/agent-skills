# 微信群分享版：一个检查大模型 API “有没有正常结束”的小工具

## 一句话

我做了一个**离线小工具**，专门检查大模型流式 API 的记录：这次调用到底有没有明确结束？失败有没有写原因？`usage` 和首 token 字段能不能核对？

## 为什么值得看

最近在测 DeepSeek 的三种 API 协议（chat / Responses / Anthropic 兼容）时，发现一些**不是模型能力、但会污染评测结论**的问题：

- Responses 流式调用有时没有 `response.completed`，客户端只能从“空文本”猜失败；
- Anthropic 兼容协议里，thinking 会吃掉 `max_tokens`，visible text 为空；
- 不同协议的 `usage`、`first_token` 口径不一样，跨协议比延迟/成本其实不可比。

小样本 120 次里：
- chat：40/40 成功；
- Responses：35/40 成功（5 条失败）；
- Anthropic：37/40 成功（3 条失败）。

240 次重复后，失败仍然集中在 MATH 题，说明不是纯随机噪声。

## 工具能做什么

给一批 JSONL 记录，检查 6 件事：

1. 有终止事件，就必须有终止事件类型；
2. 空文本 + 无终止事件，必须有失败原因；
3. 有文本但无终止事件，也要有失败原因；
4. `usage` 必须存在且非负；
5. `first_token_s` 必须说明口径；
6. `max_tokens` 必须有 `finish_reason`。

## 怎么用

```bash
cd skills/api-contract-check
python scripts/check_records.py examples/records.sample.jsonl
```

示例里故意放了坏记录，所以会列出违规项，命令返回 1 是正常的。

## 适合谁

- 做 LLM API 集成/兼容性测试的；
- 做 Agent 工程、需要稳定流式协议的；
- 做模型评测、被“空输出/超时/usage 对不上”坑过的；
- 想把工程问题写成可核对报告的研究型朋友。

## 边界

- 不是模型能力排行榜；
- 不包含 prompt、题面、原始输出、key、客户数据；
- “0 条违规”只说明记录可核对，不等于协议没问题。
